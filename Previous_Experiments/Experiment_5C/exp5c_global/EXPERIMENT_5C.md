# Experiment 5C: global-control synthetic cryptographic workload study

## Purpose
Compare standalone Argon2d, Argon2i, and Argon2id with experimental cascades at a common authentication-latency budget. The hypothesis is that some workload mixtures may scale less efficiently under concurrent CPU load. The previous experiment compared against controls within each variant; this experiment fixes that limitation. No actual password recovery, real credentials, GPU/ASIC testing, or proof of security is performed. No claim of research novelty is established by this script.

## Methods
Retains PBKDF2-HMAC-SHA256, SHA512, SHA3-256, bcrypt-PBKDF, scrypt, and same/mixed Argon2 variants. Adds seven PBKDF2 PRF configurations: SHA224, SHA384, SHA3-224, SHA3-384, SHA3-512, BLAKE2b, BLAKE2s. Adds ten cipher constructions: AES-CTR, AES-CBC, AES-CFB, AES-OFB, AES-GCM, AES-CCM, Camellia-CBC, Camellia-CFB, ChaCha20, ChaCha20-Poly1305. These are ten cipher/mode constructions, not ten unrelated cipher families. All tested as stages on both sides of each Argon2 variant. The experimental cipher workload uses a public synthetic 256 KiB buffer, a derived key, deterministic experimental nonce/IV, and SHA256 of the full ciphertext (including AEAD tag) as the state for the next round. This is a custom synthetic workload, **not a recommended KDF or production encryption design**. Fixed inputs, key derivation and nonces are for repeatability only; never use this construction for actual credentials/data. Reversible encryption itself does not imply added password protection. AES/Camellia modes are not independent algorithms. The complete default full-size matrix has 234 configurations with dependencies installed; quick uses smaller memory and omits fixed 92 MiB controls. `--deep` adds more splits (takes longer).

## Controls and matching
A common target is measured from Argon2id at 64 MiB, 3 passes, p=1 (16 MiB in quick). All three original baseline configurations are included, along with time-matched standalone tuning for passes 1, 2, 3, 4 (default) and p=1,2,4, memory up to 192 MiB (default). Explicit standalone 92 MiB comparisons are included if permitted by cap. Hybrid calibration uses the same parameters for both orders; independent benchmark latency, not calibration estimates, determines eligibility. A candidate must be within 5% of measured anchor latency AND within 5% of the best eligible standalone control at the same worker count, have at least 5% lower measured concurrent throughput, and have lower normalized parallel scaling. All three variants must have at least one matched control. This is a screen, not a claim of statistical significance. Best means best among tested controls, not global mathematical optimum. Compare all results, including unmatched and unsuccessful trials, to avoid cherry-picking. Low concurrent throughput also harms busy legitimate servers. No independent attacker hardware or cost model is measured. Argon2d stages retain potential side-channel concerns even when mixed with Argon2id.

## Windows PowerShell
Extract all files into one folder. Keep exp5b_core.py beside exp5c_global.py (copied original helper module). No previous experiment files are modified. Install dependencies:

```
python -m pip install -r requirements.txt
python exp5c_global.py --self-test
python exp5c_global.py --smoke --out results/exp5c_smoke
python exp5c_global.py --screen --out results/exp5c_screen
python exp5c_global.py --confirm-from results/exp5c_screen --max-workers 8 --out results/exp5c_confirm
```

Smoke checks only a small matrix; not scientific results. Optional `--quick --out results/exp5c_quick` runs the broad matrix at smaller memory with fewer repetitions. Full-size screening is substantially larger than Experiment 5B and may take considerable time; do not run other CPU-heavy workloads simultaneously. Default screen workers are 1,2,4; confirmation command above uses 1,2,4,8. Use fresh output directories. `--skip-bcrypt` is an explicit omission only if dependency unavailable. If memory check fails, lower workers or cap; report changed settings. `--confirm-from` keeps all standalone controls, selects the top five latency-matched hybrid candidates (prioritizing those passing the screening criteria), adds standalone controls at those candidates' largest Argon2 memory settings, and repeats without changing hybrid parameters. Confirmed measurements must still meet all criteria. The `passes_at_multiple_high_concurrency_levels` column requires success at every measured level >=4, with at least two such levels. A single positive result is not sufficient. Report all confirmation results. Use another computer if possible.

## Outputs
`ranking.csv` (maximum worker level), `summary.csv` (all levels), `raw_batches.csv` (individual measurements), `configs.json`, `calibration.csv` (screen only), `environment.json`, four plots. The ranking includes best global standalone, direct latency difference, throughput and scaling differences, candidate flag, whether all variants matched, Argon2d flag, paired repetition count, and multi-level flag. Process RSS is sampled; it may miss peaks. Throughput includes executor overhead, thread scheduling and cipher/SHA256 overhead. Repeated batches are randomized within each repetition. Same machine synthetic fixture inputs and separate process per batch. The program does not claim formal significance or cryptographic security. Raw synthetic benchmarks are not optimized cracking benchmarks. No guarantee a hybrid wins.

## Verification
Local syntax check, AES-256-CBC known answer, original PBKDF2 and scrypt known answers, Argon2 API consistency, 100 synthetic cascade determinism/input-sensitivity fixtures with bcrypt skipped, and a global ranking regression fixture. Smoke tested locally (9 configs, 18 batches, all variants). Local environment lacked bcrypt; the full calibration/screen and confirmation are untested at delivery. Verify locally before citing results.
