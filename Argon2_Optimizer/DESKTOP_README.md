# Windows desktop edition

The graphical app uses the expanded local CPU optimizer and bundled RTX 4090 measurements. Normal optimization does not require a GPU; version 4 optionally generates local GPU benchmark profiles using a bundled engine. The original source and validation data are retained for the research submission.

## Create the standalone Windows executable (once)
1. Extract the entire archive to a normal writable folder.
2. Double-click `Build_Windows_EXE.bat`. Python must be installed on the build machine (the user's existing Python 3.13 is suitable if supported by the installed PyInstaller release); internet access is needed to install packages. The script installs dependencies, obtains the pinned official Hashcat 8.0.0 archive (or uses `hashcat-8.0.0.7z` placed beside the BAT), retains its license and runtime files, runs the known-answer and unit tests, packages the app, and checks the packaged engine version. The builder logs upstream archive and executable SHA-256 values. The automatic HTTPS download is not independently PGP-verified; verify the upstream archive/signature yourself and supply the verified archive for a reproducible release.
3. Open `dist/Argon2Optimizer.exe`. This is the distributable, single-file Windows executable. Copy that EXE to another compatible Windows system; it embeds the Python runtime, required libraries, RTX 4090 profile and pinned Hashcat 8.0.0 engine. Python, PowerShell, and a separate Hashcat installation should not be required by recipients. Share `dist/release_provenance.json` and `dist/package_selftest.txt` alongside the EXE for research reproducibility. The binary is unsigned unless you separately sign it.

If you only want to run the GUI from source, double-click `setup_windows.bat` once and then `Launch_GUI.bat`.

## Use
Choose one of the five optimization tabs (Maximum defense, Balanced, Responsiveness, Resource efficiency, Comprehensive). The settings are shared between tabs. Responsiveness and Resource efficiency require a maximum stored GPU H/s target; 1000 H/s is an editable example, not a security standard. Balanced minimizes the latency × GPU H/s product; Resource efficiency minimizes CPU time first, with memory tie-breakers. Comprehensive reports the confirmed Pareto frontier and a defense-first reference. All modes except Maximum defense screen all eligible configurations and may take longer. Dark mode is enabled on startup by default. Toggle Dark mode at the top right at any time. Enter your latency budget, per-request memory limit, worker count and confirmation rounds. Optional limits may be blank. Additional compatible JSON GPU profiles can be selected; the default RTX 4090 remains included. Choose a writable results parent folder once. The app remembers it across modes and restarts; Change results folder lets you change it. Click Start optimization. A mode-specific timestamped run folder is created (`argon2_run_maximum_defense_YYYYMMDD_HHMMSS_ffffff`, `argon2_run_balanced_…`, `argon2_run_responsiveness_…`, `argon2_run_resource_efficiency_…`, or `argon2_run_comprehensive_…`), and progress plus the report appear in the window. Stop terminates the current process; partial data are not a completed recommendation. Open results folder to access the JSON, CSV, Markdown report and log.

The GUI deliberately exposes the conservative default policy only. Research-relaxed, explicit exhaustive-defense and profile-import CLI operations remain available in the source edition. The original data and code are retained in the archive but only the necessary profile is packaged into the executable.

## Verification and limitations
The build script is intended for native Windows; PyInstaller does not cross-compile Windows applications from Linux. No Windows executable has been compiled or executed in the preparation environment. The original and new unit tests, GUI tab switching, theme toggle, busy controls, and bounded live balanced-mode benchmark have been tested locally; final GUI rendering, Windows packaging and standalone execution on a separate computer require verification. An unsigned locally built executable may produce a Windows SmartScreen warning; do not bypass security policies on managed computers. The EXE is not evidence of universal optimality or cryptographic security.

## Generate and resume a GPU profile

1. Under Attacker hardware profiles, choose **Generate GPU profile…**. Read the warning. Normal CPU-only optimization remains unchanged.
2. The Windows release automatically resolves its embedded Hashcat 8.0.0 engine, extracting it on first use to `%LOCALAPPDATA%/Argon2Optimizer/gpu_engines/`. It needs no separate Hashcat installation. A source-only build without the engine offers manual selection of an existing official Hashcat executable instead. GPU drivers and backend runtimes remain external requirements.
3. Choose CUDA (NVIDIA) or OpenCL (supported GPU drivers). Use View devices to see the IDs for the chosen backend, then enter the single GPU's backend device ID. Start GPU collection.
4. The collector benchmarks the 193 exact Argon2id configurations in the bundled database, with two repetitions each and 18-second timed GPU workloads. It verifies each synthetic known input before accepting measurements. Only public, generated synthetic inputs are used. It first runs the 64 MiB, t=3, p=4 reference as a compatibility gate. The RTX 4090's original 386 corresponding timed runs occupied about 2.12 hours, excluding known-input checks and other overhead. Expect roughly 2–4 hours on a similar system; other hardware can take much longer.
5. Click **Pause GPU collection** to finish the active measurement and save its checkpoint before pausing. The app also offers to pause safely when closing. A single measurement can take longer than 18 seconds due to compilation/verification; a timeout is enforced. Wait until the status actually says paused before shutting down.
6. Click **Resume GPU profile…** to reopen the last job or choose its `argon2_gpu_profile_...` directory. Completed measurements are skipped. The saved job requires the same machine/device/backend and Hashcat binary/version. Keep the hardware, driver, software, and power settings unchanged. If you change them, create a new profile.
7. At completion `gpu_profile.json` is saved in the job folder and the app offers to add it to the attacker profiles. Failed configurations are excluded rather than treated as zero speed; only configs with both valid rounds are included. Profiles with partial coverage shrink the common optimization grid. Do not share raw job directories publicly without reviewing local paths and logs; the JSON profile is the portable output.

Hashcat's GPU temperature abort is set to 85°C, and absent temperature telemetry or a thermal abort pauses collection without accepting that measurement. This is not a guarantee against overheating; monitor core/hotspot/memory temperatures and keep adequate ventilation. If the reference test fails, inspect GPU logs and correct the setup before resuming. CUDA and OpenCL support varies with the driver, GPU, and Hashcat build. The program does not install GPU drivers or vendor runtime components. The built release includes the upstream Hashcat package and notices; its source is https://github.com/hashcat/hashcat/tree/v8.0.0 . A newly generated profile has two repetitions per configuration, unlike the 20-run confirmed subset of the bundled profile. Profiles are empirical and not a proof of security.

Version 3 verification: the 14 unit tests passed; shared folder persistence, mode names, dark theme, tab/busy controls, real historical GPU log parsing, simulated GPU profile completion and pause/resume were checked on Linux. No live GPU or native Windows executable test was performed here. Validate the first reference benchmark on actual hardware before relying on the generated profile.

## Version 4: distribute without local build steps

The **source ZIP is not itself a compiled executable**. Build once on Windows using the BAT or use the included `.github/workflows/build-windows.yml`. The latter builds on a Windows x64 GitHub Actions runner, runs a packaged CPU known-answer/profile and Hashcat version check, and exposes `Argon2Optimizer-Windows-x64` as a downloadable artifact. To use the workflow as written, put the contents of this source folder at the root of a GitHub repository, enable Actions if necessary, open Actions > Build Windows executable > Run workflow, then download the artifact after a successful run. If placing the optimizer under an existing project subdirectory, change the workflow's build working directory and artifact paths accordingly. The workflow has not been executed in the preparation environment. A real GPU is not required for the packaging check and it does not exercise GPU collection.

For a local build using an independently verified archive, place `hashcat-8.0.0.7z` beside `Build_Windows_EXE.bat`, or use `python build_windows.py --hashcat-archive <path> --sha256 <verified-digest>` after installing requirements. The download source is https://hashcat.net/hashcat/ ; the publisher provides PGP signatures there. Do not use a modified working Hashcat directory as a distribution source.

The build retains the full upstream release and its notices (including docs/license.txt), rather than claiming to implement GPU hashing ourselves. The package will be larger and first GPU use may need extra disk space. The runtime engine cache is versioned by the bundled archive digest; pause/resume uses the same engine and existing job identity checks. Older paused jobs cannot silently substitute a mismatched binary.

Verification: 18 local unit tests passed, including test-fixture engine packing/extraction, stable cache reuse, resume binary identity, rejection of unsafe archive paths, and missing licenses. CPU known-answer test passed. The preparation environment lacks a Windows runner and could not download the upstream binary archive; neither the actual archive packaging nor a Windows executable or live GPU run has been verified here. The optimizer's selection logic, default dark theme, saved-results settings, naming, bundled GPU data and GPU benchmark protocol were not changed.


## v4.1 build fix
The official Hashcat 8.0.0 archive uses BCJ2, which py7zr does not support. The build now tries installed 7-Zip, then the Windows system tar.exe. It checks extraction success and expected release layout before running the version check. If neither works, install current x64 7-Zip from https://www.7-zip.org/ and rerun the BAT. No change to optimizer code or GPU data. Only the builder needs the extractor; recipients still receive the standalone EXE. A fresh official archive is used, not a previously used Hashcat folder. An independently verified upstream digest or signature is still recommended; the download alone is not signature verification.
